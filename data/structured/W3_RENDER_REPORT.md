# W3 报告：模板格式渲染（docx）

## 一、目标

把 W2 生成的 `LessonPlan` 渲染成 docx，要求**字体、段落格式、表格排布与教师原模板一致**。

## 二、核心策略：父本克隆

不重新搭表格，而是**以原始语料 docx 为父本**：

1. 复制一份原始 docx（`第一周-劳动最快乐(1).docx`）作为骨架
2. 掏空 `body`，但保留末尾的 `sectPr`（页面尺寸、页边距、纸张方向）
3. `deepcopy` 父本的表0（标题单格）与表1（主表），原样插入
4. **只改文本，不动任何 XML 格式属性**

这样 `styles.xml` / `theme` / 表格边框 / 列宽 / 行高全部**天然继承**，无需复刻。

### 为什么不用「从零建表 + 硬编码样式」

原模板是不规则合并表（`gridSpan` 从 1 到 6），硬编码要还原：

- 17 个逻辑列的宽度（`785 / 1106 / 1106 / 971 / 1291 / 1291 / … / 356 / 813`）
- 每一行的 `trHeight`（`atLeast` 规则，各行不同：540 / 1058 / 865 / 432 / 472 / 786 / 837 …）
- 每个单元格的 `tcBorders`（四边 + 内部全部 `single` / `sz=4`）
- 竖排栏目（「教 学 过 程」「材 料 准 备」）的手工空格 + 换行排版

任何一处抄漏，产物就和模板不一致。父本克隆直接规避整类问题。

## 三、提取到的真实样式规格

来源：`STYLE_RAW.json`（从原 docx XML 提取）+ `STYLE_SPEC.md`

| 项目 | 实测值 |
|---|---|
| 统一字号 | **12 pt**（小四），仅 4 处为 14 pt |
| 东亚字体 | 显式设置为「宋体」的位置极少，其余继承样式 |
| 表格边框 | 四边 + `insideH` + `insideV` 全部 `single`，`sz=4`，`color=auto` |
| 行高规则 | `atLeast`（最小值），非固定值 |
| 表头对齐 | `CENTER`（水平居中） |
| 表0 标题 | 1 行 × 1 列，行高 480 |
| 表外段落 | `任课老师：…  时间：2025年X月X日` |

## 四、关键技术坑（三个，全部实测踩到）

### 坑 1：`cell.text = "..."` 会毁掉字体

python-docx 的 `cell.text` setter 会**推倒重建整格**，run 上的 `rPr`
（字体 / 字号 / 加粗）全部丢失。

正确做法（`_set_cell_text()`）：

1. 取格内第一个带 `rPr` 的 run，`deepcopy` 其 `rPr` 作为格式模板
2. 删掉格内所有 run
3. 新建 run 写第一行，把模板 `rPr` 装回去（`rPr` 必须是 run 的第一个子元素）
4. 其余行用 `<w:br/>` 挂在同一 run 里换行

### 坑 2：`row.cells[1]` 不是第 2 个格

python-docx 的 `row.cells` 会**按 `gridSpan` 展开**，合并格在列表里重复出现。
父本「教学过程」行第 0 格 `gridSpan=6`，于是：

```
row.cells[0] → tc0（教学内容竖排栏）
row.cells[1] → 仍然是 tc0！  ← 陷阱
row.cells[6] → 真正的正文格
```

**症状**：教学过程正文写不进去（写到错误的格上）。

**修复**：新增 `_logical_col_to_tc()` / `_cell_by_logical_col()`，
按 `tc_spans()` 做「逻辑列 → 原始 `<w:tc>` 下标」映射。

### 坑 3：`id()` 去重导致真实姓名全部漏检

遍历合并单元格去重时用了 `id(cell._tc)`：

```python
if id(c._tc) in seen:   # ❌
    continue
```

python-docx 的 `_Cell` 是**临时包装对象**，同一行循环结束后对象被回收，
下一行新建的 `_Cell` 可能拿到**相同的内存 id**，于是大量真实单元格被
误判为「已见过」而跳过。

**症状**：姓名泄漏校验对父本报 0 项违规（应有 30+ 项）。

**修复**：把 `cell._tc`（lxml 元素，在文档树里存活、身份稳定）本身放进集合。

### 坑 4：表0 标题表被误当成主表渲染

`render_preview.py` 里 `if ti == 0: continue` 的分支虽然提前跳过了，
但后续主表渲染时用 `ti == 1` 判表头底色，一旦文档表序变化（或表0不存在）就会错位。
更麻烦的是表0 是「单行单格」的标题表，用 `row.cells` 遍历时会得到重复格。

**修复**：表0 单独用一个 `class='title-tbl'`（无边框、居中、16pt 加粗）渲染，
并用 `c._tc` 去重后才输出。主表一律 `class=''`，表头底色靠**行内首格文本判据**
（`活动班级`）+ 行号 `ri == 0`，不再依赖表序 `ti`。

### 坑 5：HTML 预览的 `vertical-align` 用错值

原预览写 `vertical-align:top`，导致竖排栏目（「教 学 过 程」）和右侧个别化表
在长行里顶部对齐，看上去和原 docx 不一致。原 docx 是**垂直居中**。

**修复**：`td` 默认 `vertical-align:middle`，竖排栏位另加 `writing-mode:vertical-rl` +
`letter-spacing:.4em` 复刻手工空格排版。

### 坑 6：`run.text = ...` 会连 `<w:tab/>` 一起吃掉

「任课老师：/时间：」改用右对齐制表位后，日期仍然没贴到右边界。
根因：`_fill_meta()` 用 `runs[1].text = f"时间：{date}"` 回填，
而 python-docx 的 **`run.text` setter 会清空该 run 的所有子元素**
再塞一个 `<w:t>`，把前一步刚插入的右对齐制表位 `<w:tab/>` 一并删掉。

**修复**：写一个 `_set_t(run, text)` 辅助函数，只定位并改写 run 内的
`<w:t>` 文本节点，保留 `<w:tab/>` 等其它子元素。

### 坑 7：漏字条文导致支持轴断裂（「在」残留）

范例原文常漏字，如 `能在少量辅助通过障碍物…`（缺「下」）。
`_strip_support_words()` 的正则 `能?在?下` 剥不掉这个孤立的「在」，
剥完主干变成 `在通过障碍物把动物送回家`，与同轴另两条的
`通过障碍物把动物送回家` 不一致 → 该条被踢出支持轴、误判为发展轴 →
**相邻两层的目标组合撞成一样**（当时是 3 层制的 L2/L3），分层退化。

**修复**：剥词后补一刀 `t.replace("在","")`（连同 `能`/`下` 残留一起清），
并统一剥掉引号，避免 `送“回家”` 与 `送回家` 主干不一致。

### 坑 8：主表列索引不能用 `row.cells`

「教学过程」栏的单元格 `gridSpan=6`，`row.cells` 会把后续列索引整体推后 5 位，
读第 7 列实际拿到的是第 2 列。诊断脚本因此一度误报「列错位」。

**修复**：一律按 `<w:tc>` 原始顺序取格（`row._tr.findall(qn("w:tc"))`），
个别化表固定列索引 `C_GOAL=2 / C_NAME=3 / C_TARGET=4 / C_EVAL=6..10`。
文档本身没有错，是诊断方法错。

### 坑 9：`_short_goal()` 把「能」剥掉后成了残句

原正则 `^能?在?[^，。；]{0,8}(辅助|提示|示范)下` 把句首「能」一并剥掉，
输出「完成看图指出事项名称」这种无主语短语，读起来像排版错误。
且若把辅助量词也剥净，同一支持轴的 3 条会压成**完全相同的文本**，
表格里就看不出分层 —— 那正是这张表存在的意义。

**修复**：只把「在…辅助下」的框架压成短标记、**保留辅助量词**：
`能在全辅助下通过障碍物把动物送回家` → `能在全辅助下通过障碍物把动物送回家`；
`能自己…` → `能独立…`；另外去掉手写重复词（`独立独立`→`独立`），
截断时补齐未闭合的引号。

### 坑 10：父本的「隐形行」—— 行高压到近零，幼儿在阅读器里"消失"

**现象**：用户反馈"只列出了 11 个人"，但文件里 `S01…S12` **12 个一个不少**。

**根因**：父本 `劳动最快乐` 的数据区里混着几行行高被压得极端的行：

```
r10 h=  99      ← S05
r13 h=  90      ← S08
r17 h= 184      ← S12
其余行 h≈780~930
```

`99`/`90` twips ≈ **0.16~0.17 cm**。`w:trHeight` 只写了 `w:val` 没写
`w:hRule`，Word 按 **`auto`** 处理 —— 内容一多就裁切、行高实际塌到 0。
阅读器里那三行几乎不可见，用户自然数成 11 人。

**修复**（`render_docx.py`）：

- 新增 `set_row_height(tr, twips, rule="atLeast")` —— **必须显式写 `hRule`**。
  用 `atLeast` 保证"至少这么高"，既不压行、又能随内容长高。
- 新增 `normalize_region(tbl, r0, r1, col_start, col_end, row_twips)` ——
  把指定矩形区域内每一行设为**同一行高**。
- 新增 `unmerge_cell(tc)` —— 删掉 `w:vMerge`（`restart` 和裸 `continue`
  两种形态都要删），使格子真正独立。

### 坑 11：「个别化差异目标」漏掉第 1 条的小标号

**现象**：该栏首行渲染成 `能够在课堂上安坐不走出位置2.能在全辅助下指认国旗。`
—— 第 1 条与第 2 条**粘在一起**，看起来像缺了标号「1」。

**根因**：早期实现为了"对齐部分范例写法"，对 `index == 1` 的条文**不加编号**。
范例里确实两种写法都有，但省掉编号后与后面带编号的条文粘连，读者必然误判。

**修复**：`_layer_goal_text()` 统一为 `f"{it.index}.{it.text}"`，
**每一条都带「N.」编号**，与「康复目标」列引用的序号一一对应。

### 坑 12：8 个格要求"独立等高、不合并、不改格高"

用户原文诉求：

> 使儿童姓名往右的 8 个格以及向下到活动延伸之前的所有单元格都呈现为
> 一个个等高的独立格子，若无人填写则保持空白，不要合并或改变格子高度。

定位：
- **8 个格** = 逻辑列 8~15：`儿童姓名 / 康复目标 / 康复基线 / 第一次~第五次`
- **向下到活动延伸之前** = 表头首行（含「儿童姓名」的那行）… 最后一个数据行
  （本例 r04~r17，共 14 行）

处理：`normalize_region(tbl, head_first, tail_now-1, COL_CHILD, COL_EVAL1+4, row_h)`，
行高取区域内现有行高的**中位数**（下限 700 twips ≈ 1.23cm，保证单行文字完整）。
空文本保持空，不填占位符。

⚠ 注意 `tail_i` 是按增删行**之前**的行表算的，规整时必须按**最新行表重算**
（否则增删行后越界，实测报 `IndexError: list index out of range`）。

### 坑 13：表格网格列数 ≠ 各行 span 合计（**最难发现的一个**）

**现象**：右半张表（儿童姓名往右的 8 列）被挤成细条，`S01` / `123`
被迫**逐字换行**，看起来像一列一个字；下方空格也是一条一条的窄缝。

**根因**：父本 `第一周-劳动最快乐(1).docx` 的 `tblGrid` 有 **17** 个 `gridCol`：

```
[785, 1106, 1106, 971, 1291, 1291, 189, 1102, 441, 369, 369,
 369, 369, 369, 369, 356, 813]
```

但**除了 `活动延伸` 那一行**，其它所有行的 `gridSpan` 加起来都是 **16**：

```
教学过程(1) + 正文(6) + 个别化(1) + 儿童姓名(1) + 康复目标(1)
+ 康复基线(1) + 评量效果(5) = 16
```

而 `活动延伸` 行是 `sp1 + sp15 + sp1 = 17` —— 比人家多一个**空白尾格**。
就是这一行把网格"撑"到 17 列，末列 `813` twips 无人认领却仍占位，
于是所有单元格被等比挤窄。

**对照**：正确范例 `第五周-童心向党(1).docx` 是 **16 列网格 / 16 span**，
完全一致，渲染正常 —— 正是用户截图里的"正常样子"。

**修法**（`normalize_grid(tbl)`，在 `_fill()` 开头调用）：

1. 用**众数**（不是最大值）确定主体列数 —— 20 行里 19 行是 16，众数即 16。
   ⚠ 用最大值会取到 17（被那行异常行带偏），永远修不掉。
2. 把 span 超标的行**删掉末尾空白 tc**，使其回到 16。
3. 裁掉多余的 `gridCol`，同步 `tblW`。

修完：网格 16 列、20 行 span 全为 16、`tblW=10852`，末 8 列宽度
`4.06% + 3.40%×6 + 3.28%`，与范例一致。

**教训**：从复杂模板克隆表格时，**必须校验 `tblGrid` 列数与各行 `gridSpan`
合计是否一致**。Word 会容忍这种不一致（照样打开），但渲染结果会整体错位 ——
这类"能打开、但排版歪掉"的缺陷最难靠肉眼在 XML 层面发现，
写进自动校验（`final_audit.py` 现在会报「主表网格 20行 × N列」）最省事。

### 坑 14：「个别化差异目标」的句式被擅自改写

用户明确指出：

> 我给你的范例不是写"能在辅助下完成指认""能在辅助下完成说出"，
> 我说了只修改不符合主题的名词，其他句式之类的不要动。

我上一轮用的是《第五周-童心向党》的句式（`能在全辅助下指认党旗。`，
且原文**无逐条编号**、末条 `能自己主动是爱国。` 语法本身也不通）。
用户要的是《第四周-三月三》那一族的句式。

**正确写法**（句式照抄三月三，只换名词）：

| 三月三原文 | 国庆节到了 |
|---|---|
| 整节课堂能安坐好不走出位置不闹情绪 | 1.整节课堂能安坐好不走出位置不闹情绪 |
| 2.能在**身体辅助**下**完成指认**三月三习俗名称 | 2.能在身体辅助下完成指认**国旗** |
| 3.能在**少量手势辅助**下完成指认三月三习俗名称 | 3.能在少量手势辅助下完成指认国旗 |
| 4.能**自己独立完成**指认三月三习俗名称 | 4.能自己独立完成指认国旗 |
| 5.能自己看图表达表达三月三习俗名称 | 5.能自己看图表达**国旗的颜色和五角星** |
| 6.能参与**抛绣球**的游戏 | 6.能参与**国庆节的庆祝**游戏 |

**教训**：「只改名词」是**逐字级**要求 —— 辅助量词（身体辅助 / 少量手势辅助 /
自己独立完成）、动词（完成指认 / 看图表达）、句式一律照抄，只替换实体名词。
不要"顺带优化"句子结构，也不要照搬另一份范例的句式。

### 坑 15：「康复基线」列被留空（**基线是随教案传递的，不能空**）

用户指出：

> 这是用哪个为前一教案制作的啊，康复基线不应该根据上一教案填写吗

我一开始把「康复基线」当成"本课新测、课后才有"的列，全部留空。
全语料扫描（14 份 docx / **189 条**儿童记录）后，三条硬事实：

**事实 1 —— 该列从不留空**：189 条记录里空值 **0 条**。

**事实 2 —— 记号个数恒等于「康复目标」的编号个数**：可比 178 条，
`178/178` 全部一致。目标 `1456` 配 4 个记号（`P  P PP`），
目标 `145` 配 3 个记号（`P  EE`），中间的空格只是**与编号逐位对位**的
书写留白。→ 它是**逐条目标的评量**，条数跟着本课目标条数走。

**事实 3 —— 跨教案传递**：27 名出现 ≥2 次的幼儿里，**12 名的基线串
一字不差**：

| 幼儿 | 目标 | 基线 | 出现的教案数 |
|---|---|---|---|
| 卢炜彬 | 1245 | `P  P PP` | 5 份 |
| 姚志楷 | 1245 | `P  P PP` | 5 份 |
| 杨弘毅 | 123 | `P  EE` | 5 份 |
| 莫冠希 | 123 | `PEE` | 5 份 |
| 杨祥彬 | 1456 | `P  P PP` | 5 份 |
| 朱品合 | 134 | `P   PP` | 4 份 |

且它是**能力属性**、不是"上一节课的评量结果"：蒙智宇在《第五周-童心向党》
五格评量全是 `未参与`，基线仍是 `PEEE` —— 与更早的《第一周-快乐六一》
完全一样。说明基线只在目标组合变化时才重写。

**结论**：基线 = "这个孩子接手本课时处在什么水平"，与右边的
「评量效果」（"上完本课后到了什么水平"）构成前后对照。新教案必须
从**前一教案**取，不能留空。

#### 实现（三次返工）

**第一版：按行序取** —— 直接拿上一教案第 i 行的基线给第 i 个孩子。
问题：上一教案的名册与本课在课名单**不是同一批人**，等于把 A 孩子的
基线和安到 B 孩子头上。

**第二版：按身份取** —— 用私有映射 `data/private/name_mapping.json`
（`Sxx ↔ 真实姓名`，仅内部取数、不写进产物）还原身份，再去上一教案找
**同一个孩子**的基线。先验证了该映射可靠：用评量达标率交叉验证 35 名，
画像与语料吻合 28 名（80%，其余差异来自"只采信可靠领域"的口径）。
修完发现只匹配上 4/12 —— 因为 12 人是从 37 名画像里抽的，
上一教案的实际名册只有 14 人。

**第三版：在课名单先取上一教案的名册** —— 把抽样池限定为上一教案的
在课名单，再按本课主领域分层抽 12 名。修完 **12/12 全部身份匹配**，
0 条兜底、0 条推演。

#### 另一个坑：记号个数要按本课目标条数校正

上一课评 4 条、本课只评 3 条时直接照搬会得到"4 个记号对 3 条目标"。
新增 `fit_baseline(s, n, layer)`：长度相同原样返回（连空格写法一起保留）、
多了截尾、少了按层级补（L2/L3 补 `P`、L1 补 `E`），并沿用原串的间隔模式。

⚠ 边界：`fit_baseline` 遇到**不含 P/E 的串**（范例里的 `未参与`
缺勤标记）必须**原样返回**。早期版本返回空串，导致那名幼儿的基线格变空白。

#### 抽数时踩到的次生坑

`《第四周-能干的我》` 和 `《第四周-浓浓端午节》` 这两份范例里，有 4 行的
「康复目标」单元格被 P/E 串挤串（读到 `c4='P   PP'`）。如果按
`c4.isdigit()` 筛行，这 4 名幼儿会被整行丢掉 —— 表现为 15 人的班
只取到 11 条基线、后 4 行留空。
**修法**：只要求**姓名非空**即认行，基线优先取第 6 格、被挤串时回退第 5 格。

配套审计脚本：`scripts/verify_baseline.py`（语料统计 + 身份对齐 + 产物校验）。

### 坑 16：名册要列**全班**，且「康复目标/基线」按幼儿本人最近记录延续

用户要求：

> 对于未参与的情况，请在康复基线中统一标注为「未参与」……
> 关于副作用部分，请补充其他目前未出现在认知课《国庆节到了》中的幼儿代号，
> 并依据包含其姓名的最新日期范例，补充康复基线与康复目标。

上一版把在课名单**抽样到 12 人**（用上一教案名册当池子，保证基线能按身份承接）。
副作用是四份教案的名册变成同一批人、且漏掉了班里其他幼儿。

**改法**：名册 = **全班在册幼儿**（37 人，含缺勤），每位幼儿的两个值取自
**他/她最近一次有记录的教案**（`scripts/roster_from_corpus.py`）。
「最近」按 `lessons.json` 的 `date_range` 起始日排序。

这样做的依据（实测 189 条记录）：

1. `康复基线` **空值 0/189**；
2. **记号个数 == 该幼儿「康复目标」编号个数，178/178 无例外**；
3. 同一幼儿的目标组合与基线**跨教案高度稳定** —— `陈映燊 1456 / P  P PP`
   连续三份、`卢炜彬 1245 / P  P PP` 连续四份、`朱品合 134 / P   PP` 四份。
   说明这两列本来就是**随教案延续的个别化方案**，不是每课重算。

#### 「未参与」的判定

范例里 `康复基线` 写 `未参与` 的触发条件 = **该幼儿整轮未参与**：

```
第三周-浓浓端午节   蒙智宇   基线 未参与   五次评量 全 未参与
第四周-清凉夏日     蒙智宇   基线 未参与   五次评量 全 未参与
反例（只缺某几次，基线照常）：何侦霖 P  EE、陈映彤 P  EE、覃芯玥 PEE
```

所以规则：该幼儿**最近一次记录的五次评量全为「未参与」**（或基线格直接写
「未参与」）→ 基线写 `未参与`；否则用记录里的原串。
产物里 37 人中命中 3 人：**S15、S16、S37**。

`fit_baseline()` 对不含 P/E 记号的串**原样放行**，不会被清空
（这是坑 15 之外新加的边界，早期版本会把 `未参与` 洗成空白格）。

#### 超界序号的取舍 → 升级为「可解释」判据

跨教案取来的编号是**那份教案的序号**，各课阶梯条数未必相同
（《第二周-动物的家》只有 5 条，编号里的 `6` 在本课不存在）。

早期处理是「剔除超界序号、剩下 ≥3 条就用」。**现已收紧**：编号必须
**全部**落在该课阶梯内、且条数 ≥3，才算**可解释**（`lesson_flow.interpretable`）；
不可解释就**往前回退**到更早的记录，全部不可解释才回落画像判定。

为什么收紧：各课编号含义不同（本课「4」是独立档，别课「4」可能是进阶条），
拿一份残缺的编号去解释会算出**错的层**（实测某幼儿被算成 L1、而画像明明是 L4）。
收紧后该幼儿改由其更早一条完整记录（组合 `156`）定为 L4，与画像一致。

产物实测：**26 名按组合规律定层、11 名画像回落**（其中 9 名全班只有一份
`闪电班4月21日主题教案` 的记录，而该课阶梯未从范例恢复）。附录表三写明来源。

#### 判定依据必须与层级同源（本轮修正）

曾出现「判定依据写 L4、层级却是 L1」的自相矛盾行 —— 根因是**两套口径**：
层级来自组合规律、依据来自能力画像。现改为：凡从记录定层的，依据改用
**组合规律口径**（「本人最近记录（日期）组合 156 属 R+S3+A1 规律 → L3」）；
画像回落的，依据保持画像口径。表三下方另加一句「定层来源：X 名按组合规律 /
Y 名按画像判定」。

> 后续用户把交付范围收窄为**只保留《国庆节到了》**，其余三份已归档。
> 上表数据保留为机制验证记录（说明「截断超界序号」这条规则确实生效）。

#### 行高不能再从中位数算

坑 12 里统一行高用的是「区域内现有行高的**中位数**」。名册从 12 人扩到 37 人
后，中位数从 **837 漂到 786** —— 同一种格式在两版之间行高不一致。
改为固定常量 `DATA_ROW_TWIPS = 837`（用户已认可那版的实测值）。

#### 审计规则同步放宽

`final_audit.py` 原来断言「康复目标组合**恰好 3 种**」—— 那是三层机制的产物。
现在每位幼儿按本人记录延续，组合自然多于 3 种。规则改为守这几条：
1. 组合长度 3~4、数字不重复、序号不超出本课阶梯条数；
2. 「康复基线」非空，且 `未参与` 与「记号数 == 组合条数」各自成立；
3. 分层机制没被删掉，且**层数 = `layer_count()`（按组合规律算出，现为 4）**，
   `L1…L4` 都还有人；附录二标题写「N 个层级与目标组合」，不再写死「三层级」。

#### 顺手合并了两套行定位规则

`verify_baseline.py` 里原本另有一份「找表头行 → 按列名索引」的读取实现，
与 `run_render.py` 的「按固定列号取」不一致，同一份范例在两处抽出的人数
不同（15 vs 11）。两份已合并到 `roster_from_corpus.read_lesson_rows`，
`verify_baseline.corpus_rows` 只做转发。

## 六、个别化差异目标表的处理

用户要求「表头 + 匿名占位行」。在**文本层面零身份**约束下的具体做法：

| 列 | 内容 | 说明 |
|---|---|---|
| 个别化差异目标 | 该层所选条文的短文（`_short_goal()` 压缩） | 群体目标，非个体目标 |
| 儿童姓名 | `S01` … `S37` | 匿名编号，不含姓名 / 诊断 |
| 康复目标 | **条文序号组合**（连写如 `1456`） | 与范例写法一致，见下 |
| 康复基线 | 该幼儿**接手本课时的能力水平**（`P/E` 串） | ⚠ 早期版本一度留空，实测 189 条范例记录**空值 0 条**，该判断是错的 —— 见 6.5 |
| 第一次~第五次 | 留空 | 待老师手填 |

行数 = 本班在册人数 = **37**（不是 `class_profile.class_size`）。

### 6.1 「康复目标」列为什么写编号组合

**这是本轮最重要的领域发现。** 范例 `康复目标` 列的 `1345` / `1456` / `126`
不是「第 1/3/4/5 难度档」，而是**该儿童本课所选的目标条文序号集合**，
取自同表左侧「个别化差异目标」栏的编号条文。三条证据见 `LAYERING.md`：

1. 每个数字都能在左栏找到对应条文，一一对应、无跳号；
2. 编号集合大小 3~4 浮动（13 份范例、170 条记录，`avg=3.37`），
   若代表固定三档则必然恒为 3 个数字；
3. 条文排列是**双轴**——支持轴（全辅助→少量辅助→独立）+
   发展轴（指认→表达→听令），不是单轴难度。

因此分层 = **按能力给每个孩子选条**，不是给数字分组。

### 6.2 层级的目标组合（**层数由组合规律决定，现为 4 层**）

层数**不预设**：数语料里「康复目标」的组合规律有几种，就分几层。
13 份范例、170 条记录里的组合只落在 **4 种轴位形态**上（`R`＝课堂常规、
`Sk`＝支持轴第 k 档、`Ak`＝发展轴第 k 条）：

| 层 | 名称 | 组合规律 | 所需支持 | 基线 P 密度 |
|---|---|---|---|---|
| L1 | 高支持层 | `R+S1+S2` | 身体辅助 | 0.48 |
| L2 | 中支持层 | `R+S1+S3` | 少量手势辅助 | 0.56 |
| L3 | 低支持层 | `R+S3+A1` | 独立完成 | 0.80 |
| L4 | 泛化层 | `R+S3+A1+A2` | 独立完成并泛化 | 0.92 |

P 密度单调递增，是分层成立的**独立证据**（复算 `scripts/mine_layer_tiers.py`
→ `data/structured/layer_tiers.json`）。层数由 `layer_count()` 读该 JSON 得到，
**代码里没有 3/4 的硬编码**。

本课（《国庆节到了》，6 条阶梯）各层组合：

| L1 | L2 | L3 | L4 |
|---|---|---|---|
| `1、2、3` | `1、2、4` | `1、4、5` | `1、4、5、6` |

条文 1 恒为课堂常规，人人必选，与能力无关。

> ⚠ 上表是**分层机制给出的基准组合**（"能力 → 该评哪几条"）；
> 教案正文里每位幼儿的**实际**组合取自**其本人最近一次可解释记录**的组合规律
> （个别化延续，见坑 16），因此可能与基准组合不同 —— 附录第二表下方已加注说明，
> 避免读者以为表里写错了。

### 6.3 分层结果不写进正文，另起一页附录

每份教案后追加一页「附录：儿童分层对照表」，含 4 张表：

| 附录表 | 内容 |
|---|---|
| 一、分层依据（目标阶梯） | 条文逐条编号 + 轴位标注 |
| 二、**N 个层级与目标组合** | 层级 / 定义 / 所需支持 / **组合规律** / 本课目标组合（+ 与个别实际组合的关系注 + P 密度单调递增注） |
| 三、儿童代号与所属层级 | 代号 / 层级 / 层名 / **本课实际目标组合** / **判定依据**（注明来源，且与层级同源） |
| 四、随评量结果的层级调整机制 | 代号 / 初始层级 / 第1~5次评量 / 调整轨迹 |

> 附录三、四两表现在是 **37 行**（全班名册），不再是 12 行抽样。
> 附录二标题里的 N 由 `layer_count()` 填入（现为「4 个层级」），不再写死「三层级」。

### 6.4 动态调层机制

| 触发条件 | 动作 |
|---|---|
| 连续 2 次评量达标率 ≥ 85% | 上调一层 |
| 单次评量达标率 < 40% | 下调一层 |
| 该次评量为「未参与」 | 跳过，不计分母、不触发调整 |
| 上限 / 下限 | **L4 / L1**（层数取自 `layer_count()`） |

设计理由：上调要求「连续 2 次」体现稳定性原则；下调只需「单次 <40%」
（上调谨慎、下调敏感，避免孩子在高层反复挫败）；「未参与」必须排除，
否则请假的孩子会被误降层。

**升级后的连带变化**（用户指定）：

- **康复目标** → 换成**本课阶梯上该层的规律实例**（跨课复用规律、换课换条文）；
- **康复基线** → 逐位对齐新组合：**保留的目标沿用原记号、新加入的目标记 `E`**
  （`lpa.layering.compose_baseline`，默认 `new_mark="E"`）；
- 整轮未参与 → 基线统一写「未参与」，不调层。

附录表四实测三种轨迹均可见：上调 `PEE(1/3)L1 → PPP↑(3/3)L2`、
下调 `PPP(3/3)L3 → EEE↓(0/3)L2 → PPP↑L3`、未参与不触发。

> ⚠️ 附录表四的评量序列是按能力画像**推演**的演示数据，用于展示机制走向，
> 不是真实课堂记录。真实使用时由教师每次课后录入实际评量结果，算法自动重算层级。

### 6.5 「康复基线」列的三条硬规律

实测 14 份范例、**189 条**记录，该列**空值 0 条**：

1. **记号个数 == 本课目标条数**（可比 178 条，178/178 一致）。目标 `1456` 配
   4 个记号 `P  P PP`，目标 `145` 配 3 个记号 `P  EE` —— 空格只是与编号
   **逐位对位**的书写留白。
2. **跨教案传递**：27 名出现 ≥2 次的幼儿里，12 名的基线串**一字不差**
   （如某幼儿 `1245 / P  P PP` 连续 4~5 份）。
3. **是能力属性，不是"上一课评量"的照抄**：某幼儿在《童心向党》五格全是
   「未参与」，基线仍写作 `PEEE`，与更早的《快乐六一》一模一样。

生成新教案时的取法：**沿用本人最近一次记录的基线** → 按用户指定的
「保留沿用、新增记 `E`」逐位对齐本课新组合（`compose_baseline`）；
整轮未参与则写「未参与」。

> 与语料写法的偏差（如实记录）：复算 63 对相邻记录，**保留目标 93% 沿用
> 原记号**（与规则一致），但**新增目标只有 27% 写 `E`**（48 例老师写了 `P`）。
> 本实现按**用户指定口径**执行（新增记 `E`）；若要复现语料写法，把
> `compose_baseline(..., new_mark="P")` 即可。
