## 二、必须修正的三处设计

### 1. 目标框架：不能套《3-6岁儿童学习与发展指南》

原设计按幼儿园小/中/大班套《指南》——**错了**。语料是 3—9 岁混龄康教班，超出《指南》覆盖范围。

修正为**双轴目标框架**：

- **发展领域轴**：认知、语言、运动、社交、生活自理、情绪行为
- **支持层级轴**：独立完成 / 手势辅助 / 少量身体辅助 / 大量身体辅助 / 示范模仿 / 未参与

第二根轴不是我编的，是从语料里的原话抽出来的——「能在**少量身体辅助下**指出劳动名称」「能在**少量手势辅助下**完成……」「能**自己独立**完成……」。这就是现成的分层标尺。

### 2. 能力画像：不要人工填，从评量数据反推（重要升级）

原设计让老师手填「6 维能力 × 3 级」——费劲、主观、答辩容易被问"数据哪来的"。

语料里每个孩子在每个康复目标上有 **5 次 P/E 评量序列**，可以直接反推：

| 派生指标 | 算法 | 含义 |
|---|---|---|
| 首达位置 | 第一次出现 E 是第几次 | 学会快慢 |
| E 率 | E 的次数 / 参评次数 | 稳定程度 |
| 退化检测 | 出现 E→P 回落 | 是否需要复练 |
| 综合支持层级 | 上述三项加权 → 层级轴 6 档 | 该幼儿在本目标维度的当前水平 |

再按目标维度聚合到全班 → **班级能力分布** → 决定新教案里 A/B/C 三层的人数配比和支架强度。

这条升级让整个输入层从"拍脑袋"变成"有据可查且可复现"，是报告里最硬的一块。

### 3. 去标签化：现在有硬证据了

原始文档里白纸黑字写着「★ 智力障碍、自闭症」，每个孩子挂着真名。

系统输出必须是：**无姓名、无诊断、无缺席名单、层次标记可选隐藏。**

于是「标签词泄漏率」这条指标可以做**前后对比**：原始语料命中一堆 → 系统输出恒为 0。这是答辩时最好用的一张表。

| 编号 | 含义 | 取值范围 |

## 五之三、个别化表的列结构（2026-09-29 定案，曾反复错）

真实列顺序（经原始表格截图逐格核对）：

```
个别化差异目标 | 儿童姓名 | 康复目标 | 康复基线 | 第一次 | 第二次 | 第三次 | 第四次 | 第五次
```

对应 `<w:tc>` 下标与语义：

| tc | 内容 | 说明 |
|---|---|---|
| tc[2] | 康复目标文本 | "1.整节课堂能安坐好…" |
| tc[3] | **儿童姓名** | 定锚点 |
| tc[4] | **康复目标编号** | 如 `1456` = 第 1/4/5/6 条目标 |
| tc[5] | **康复基线** | 如 `PPPP`，这几条目标干预前的达标状态 |
| tc[6]–tc[10] | **第一次~第五次评量** | `未参与` 或 P/E 码 |

### 三个必须记住的坑

1. **`1456` 不是基线，是目标编号** —— 早期当成基线，整行右移一格。
2. **基线本身也是 P/E 形态**（`PPPP`），不是数字串 —— 它描述干预前状态，
   **不属于评量数据**。
3. **「列存在」≠「有数据」** —— 空的 `tc` 也是 `tc`。
   14 份语料的表头**全部是 5 列**，但「闪电班4月21日主题教案」
   只填到第 3 次，第 4/5 列**表头存在、整列为空**。
   ❌ 曾因截取表格时把空的 `tc[9]/tc[10]` 误读成"不存在的列"，
   断言"闪电班只有 4 列"，并写进了三份报告 —— 已全部清除重写。
   ✅ 核对表格结构**必须看表头行**，不能只看数据行的截取。

定标样本（第一周-快乐六一 · 陈映燊）：目标 `1456`、基线 `PPPP`
→ 五次评量 = `未参与 → PPPE → PPPP → PPPP → PPPP`

### 解析实现要点

- **直接读 `<w:tc>` XML**（`row._tr.findall(qn("w:tc"))`），
  **不要用 `row.cells`** —— 后者把横向合并区展开成多格，列位随行漂移。
- **不要按文本内容做相邻去重** —— 会误杀内容相同的合法行
  （「春天的踪影」「我和我的同伴」目标文本全同，曾被吃掉 31 条）。
- **纵向合并需读 `w:vMerge`**，`continue` 格的文本为空，要回溯取值。
- 姓名定锚判据：`姓名 + 纯数字目标编号 + P/E 基线码`，
  且**编号位数必须等于基线码长度**（都等于目标条数）。
- 评量格字母 `F` 出现 21 次，均为键盘 E/F 相邻笔误 → `F→E`，计数留痕。
- **评量列数按表头逐表实测**（`eval_slot_count(table)`），不硬编码 5。
  ⚠ 参数必须是 `Table` 而非 `_Row` —— `row._parent` 是 `_Rows`，
  **没有 `.rows` 属性**（踩过，会导致解析出 0 条记录且不报错）。
- **`未参与` 既不进分子也不进分母**（`parse_code` 返回空列表），
  对达标率计算零影响；它只改变「这次有多少条记录可算」。

### 自检脚本（新增，跑报告前必过）

| 脚本 | 作用 |
|---|---|
| `verify_alignment.py` | 4 项断言：长度恒 5 / 只含 P/E / 编号与基线一致 / 字母数不超目标数 |
| `verify_perfile.py` | 逐份列位核对表（每次有数据的记录数） |
| `verify_rawxml.py` | 原始 XML 逐行原样输出，不做任何解析，供人工核对表头 |
| `final_consistency.py` | 32 项端到端断言，三份报告 + 两份 JSON 数字互相对得上 |

**当前状态：全部通过（断言 0 违例，一致性 32/32）。**

## 五之四、评量分析结论（口径修正后，2026-09-29）

**旧口径（错误）** 把基线当成第一次评量，得出第一次达标率 0.781 的高起点，
掩盖了真实规律。

**正确口径** 下，103 条完整 5 次评量的配对曲线
（分母固定为这 103 条，取自去重后的 164 条有效记录）：

| 第几次 | 达标率 |
|---|---|
| 第一次 | **0.141** |
| 第二次 | 0.559 |
| 第三次 | 0.831 |
| 第四次 | 0.896 |
| 第五次 | 0.907 |

**这是典型的康教干预曲线：起点极低（14%），三次课内快速拉升到 83%，
之后趋于饱和（91%）。**

- 口径 B 个体进步量：平均 **+0.611**、中位数 +0.667、进步 84%、**退步 0%**
- 口径 C 一致性：稳定达标 8(5%)、波动已收敛 145(93%)、从未达标 1(1%)、数据不足 2(1%)

**对生成层的意义（写进报告）**：

1. **第一次评量不能作为能力起点** —— 康教幼儿首次面对新目标普遍不参与，
   A 层目标的辅助强度不能按"第一次表现"定，要按**后续收敛速度**定。
2. **第 3 次是关键节点** —— 设计时必须保证有足够复练次数（≥3），
   否则看不到效果。
3. **波动已收敛占 93%** —— 说明"学得会但需要多次"是常态，复练环节必须有。

## 五之五、达标率方法论（答辩必问，先写清楚）

### 1. 公式

**单格达标率** = 该格 P 的个数 / (P+E) 的个数

- `PPPE` → 3/4 = 0.75
- `未参与` → **不生成 SessionResult，既不进分子也不进分母**
- 空白格 → 同上，不参与计算

**口径一 · 宏平均**（按记录平均，每条记录权重相同）
```
第 k 次宏平均 = Σ(每条记录的格达标率) / 参评记录条数
```

**口径二 · 微平均**（按字母平均，每个字母权重相同）
```
第 k 次微平均 = Σ(P 个数) / Σ(P+E 个数)
```

**口径 A · 配对分析**：只保留**恰好 5 次都有数据**的记录，分母锁死 103。

### 2. 固定样本数的影响（必须报告的量）

| 第几次 | 不固定分母 | 固定 103 | 差 |
|---|---|---|---|
| 1 | 0.188 (n=130) | **0.141** | **−0.047** |
| 2 | 0.561 (n=150) | 0.559 | −0.002 |
| 3 | 0.785 (n=151) | 0.831 | +0.046 |
| 4 | 0.858 (n=140) | 0.896 | +0.038 |
| 5 | 0.877 (n=119) | 0.907 | +0.030 |

- 平均绝对偏差 **0.033**
- **越靠前越敏感**：第一次相对变化 −25%
- 原因：**分母剔失非随机** —— 参与次数少的人能力弱、出勤差。
  混着算等于让「上满 5 次课的人」代表「只上 1 次课的人」。
  不固定分母时测的不是"进步"，是"谁坚持下来了"。

### 3. 达标率在项目中的**作用边界**（关键，别本末倒置）

> **达标率不是研究对象，是"分层依据"。**

```
历史评量 ──反推──▶ 能力画像/支持层级 ──聚合──▶ 班级分层分布
                      ↑ 达标率只用在这一步
                            │
                            ▼
              A/B/C 三层人数配比 + 支架强度
                            │
                            ▼
                  agent 生成分层教案（项目主体）
```

具体只干三件事：

1. **把幼儿分到支持层级**（`taxonomy.py` 的 `MASTERY_TO_SUPPORT`）：
   ≥0.80 独立完成 / ≥0.60 手势辅助 / ≥0.40 少量身体辅助 /
   ≥0.20 大量身体辅助 / <0.20 示范模仿
   → 这就是"识别不同层级幼儿"的全部技术内容，可复现、无需老师手填
2. **决定 A/B/C 三层人数配比**：读 `class_profile.json` 的领域分布
   （如语言沟通：手势辅助 12 人、少量身体辅助 5 人、大量身体辅助 5 人
   → A 层约 5 人）
3. **给出"进步速度"参照**：配对曲线 0.141→0.831（前三次）说明
   一周内三次复练从"基本不会"到"基本会"是正常的，
   防止 agent 把目标定成"一次达标"或"五次不会"

报告篇幅建议：**达标率相关控制在 15% 以内**，主体是生成链。

### 4. 一个必须注意的用法

`child_profiles.json` 里的 `mastery` 是**跨 12 份教案的累计合规达标率**，
混了不同主题的能力。生成时要**按主领域取对应领域的分层**
（用 `domains` 数组里对应领域的那条），不要用 `mastery` 总数。

### 5. 已知 limitation（写进报告）

- **未参与**不做特殊建模（用户拍板）：不建模 MNAR、不加 IPW 加权。
  通过配对分析规避，而非建模。
- 语料同源（同机构 2 个班、同一批孩子），泛化性有限。
- 达标率的分母口径已在报告中显式声明，三份报告数字含义不同、已对齐。

### 6. M4-4 已算出的结论（消融实验）

**设计**：从完整系统出发，**每次只关一个模块**，其余开关不动，同一批 4 门课

| 臂 | 关掉的模块 | W2 致命 | 四门通过 | 跨主题相似度（越低越好） | 独有文字（越高越好） | 逐字重复句 |
|---|---|---|---|---|---|---|
| `full` | ——（基准） | 0 | 4/4 | **0.11** | **82.8%** | **9** |
| `no_obj` | LLM 目标分层 | 0 | 4/4 | 0.15 | 80.4% | 8 |
| `no_content` | LLM 内容扩写 | 0 | 4/4 | **0.84** | **20.1%** | **86** |
| `no_scaffold` | 支架注入 | **56** | **0/4** | 0.12 | 78.2% | 7 |
| `no_repair` | 自检重写 | 0 | 4/4 | 0.14 | 79.3% | 7 |

（语料范例自然水位：相似度中位 **0.08**；每臂 5 个文件 = 国庆拆 2 班 + 3 个留出各 1，
五臂版式终检均 PASS。）

**三条结论**：

1. **内容主题化靠 `llm_content`，且它是唯一的大杠杆。** 关掉后相似度
   0.11 → **0.84**（水位的 7.6 倍）、独有文字 82.8% → **20.1%**、逐字重复句
   9 → **86** 条 —— 教案立刻退回「换个主题名还是同一篇」的模板状态。
   ⚠ 这组数字与 M4-2 记录的模板期（0.84 / 19.4% / 83 条）**独立吻合**，
   互为交叉验证。
2. **合规完整度靠 `use_scaffolding`。** 关掉后 7 个环节各缺「支持措施」与
   「视觉提示」，硬校验判 **56 条致命**、四门课 **0/4** 通过；但版式终检仍
   PASS —— 说明卡住的是**内容完整度**，不是版式。
3. **`llm_objectives` 与 `self_repair` 影响轻微**（相似度各 +0.04 / +0.03）。
   它们不是没用，而是当前生成质量已高，更多起**兜底与保险**作用
   （换更弱的模型或更偏的主题时才会显出价值）。

> **一句话结论**：系统的「内容质量」几乎全部由 **LLM 内容扩写**支撑，
> 「结构完整」由**支架注入**兜底；另外两个 LLM 模块是保险丝，不是发动机。

⚠ **两个踩过的坑**（已写进代码注释）：
① 关支架后 LLM 内容扩写会把支架**填回来**，导致消融臂与基准看不出差别 ——

② `ValidationReport` 的属性是 `fatal_count` / `warning_count` / `passed`，

## 九、课程交付要求对表与 Agent 化改造（2026-10-09）

课程通知（`AI Agent作业通知和报告提交规范.md`）的硬要求是
**Function Calling / 工具调用 + 多步自主决策链路 + Thought-Action-Observation Trace**，
而本项目此前是**确定性流水线**：`LLMClient` 只有单轮 `complete()`，全库零工具调用、
零 Trace 落盘。缺工具调用按「伪 Agent」扣 **10–15 分**，模块 2（25 分）、
模块 3（25 分）直接落最低档。**逐项盘点与 20 项整改清单见
`docs/SUBMISSION_GAP_ANALYSIS.md`。**

### 1. P0-1 已完成：模型层具备工具调用能力

**改动只有一处，但它是 Agent 化的地基。**

| 新增 | 作用 |
|---|---|
| `complete_raw(messages, tools=…)` | 收完整多轮 messages、**保留 `tool_calls`** —— Agent 循环的底座 |
| `run_with_tools(system, user, tools, runner, max_steps, on_step)` | **Agent 主循环**：模型自己决定调哪个工具、调几次、何时收尾 |
| `ToolCall` / `ToolRun` / `AgentTranscript` | Trace 数据结构；`AgentTranscript` **本身就是报告要的调用轨迹** |
| `tool_schema()` | 造 OpenAI 格式工具定义 |
| `_chat()` | 把重试逻辑抽成公共底座，单轮与多轮共用 |

`complete()` 签名与行为**完全不变**（W2 五个步骤照走），只是内部改调 `_chat()`。

**四条硬规矩**（都写进代码注释了）：

1. **回灌历史必须原样带回 `tool_calls`** —— 否则下一轮 `role="tool"` 消息
   找不到 `tool_call_id`，接口直接报 400。
2. **工具抛异常不中断循环** —— 异常文本转成 Observation 回灌，让模型自己修正。
   工具报错是**信息**，不是崩溃。
3. **参数解析失败不兜底** —— `arguments` 不是合法 JSON 就把错误回给模型重填，
   **绝不填默认值**（硬凑参数会静默产出一份错教案，比报错危险得多）。
4. **`max_steps` 是硬闸** —— 没有它模型会在两个工具之间无限来回。

### 2. 实测结论：`glm-4-flash` 撑得住多轮工具调用

`scripts/probe_tool_calling.py` → `data/structured/TOOL_CALLING_PROBE.md`

设计上把「链路正确性」与「模型能力」**分开测**：

| 层 | 怎么测 | 结果 |
|---|---|---|
| **链路**（与模型强弱无关） | mock 确定性替身，走**同一份** `run_with_tools()` | ✅ 收敛 / `tool_call_id` 配对不缺 / 步数 = 工具轮 + 1；**且故意让工具抛 `KeyError`，异常被回灌而未中断循环** |
| **模型**（选型依据） | 真跑，任务设计成**必须按顺序调 3 次工具**才能答（不调 `list_children` 就不知道有 S37） | ✅ **3/3 次运行全对**（每次 3 个工具调用，累计 9/9）：序列、参数、答案、收尾全对，5–7 秒/次 |

> **这条结果直接消掉了 P1-4 的最大不确定性。** 原本担心轻量免费档
> （`glm-4-flash`）function calling 能力不足、需要换成 `glm-4-air/plus` 或
> `deepseek-flash` —— **实测不需要换**。免费额度可以继续用。

单元测试：`scripts/test_llm.py` **34 项全通过**（新增 16 项工具循环测试，
含「`max_steps` 拦住死循环」的专项用例）。顺手修掉一条**陈旧断言**：
原来写死 `len(PROVIDERS) == 4`，2026-10-08 加了 ollama 后它就恒 FAIL ——
改成断言**名单**而非数量，免得假红灯让人渐渐不信任整套自测。

### 3. P0-2 已完成：10 个工具集（`src/lpa/tools.py`）

**只包装，不复制** —— 每个工具都是现有模块函数的入口，业务逻辑一行未重写：

| 工具 | 包装的既有能力 |
|---|---|

③ **顺序契约** —— 顺序错了抛带指引的错误（不静默补默认值），由 Agent 自己决定回头补哪步。

### 4. P0-3 / P0-4 已完成：LLM 自主编排 + Trace 落盘（2026-10-09）

**编排层换了，能力层没换** —— `src/lpa/agent.py` 只给模型「目标 + 工具清单 + 纪律」
（prompt 里**不出现步骤表**），顺序、重试、修复全部由模型自己决定；工具与渲染/终检
链路仍是 P0-2 那一套（同源交付）。`scripts/agent_run.py`（CLI `auto`）跑一次并落全证据。

**两次真跑（`glm-4-flash`，免费档）**：

| 场景 | 步骤 | 工具调用 | 校验轨迹 | 终检 | 结论 |
|---|---|---|---|---|---|
| 正常自主编排 | 8 | 7 | ✓（首稿过检） | exit=0 | 完整闭环 ✅ |
| 修复闭环（注入坏目标） | 10 | 9 | ✗1致命 → ✓ | exit=0 | 完整闭环 ✅ |
