# M4-5 · 教师盲评方案（人在环）

> **一句话**：把系统产出的教案和语料里真实教师手写的教案**混在一起、去掉来源标记**，
> 请一线教师按同一套量表打分 —— 因为**机器指标只能证明「像不像」，只有教师能回答「好不好用」**。
>
> | | |
> |---|---|
> | 材料包 | `data/blind-eval/`（`README.md` 是使用说明） |
> | 生成 / 统计 | `scripts/blind_eval_pack.py`（CLI：`lesson_docx.py blindeval`） |
> | 环节性质 | **独立环节**，不与 M4-1 / M4-4 的机器指标合并，也不由自动化替代 |
> | 当前状态 | 🟡 **材料已就绪，待真人教师实施**（本方案不含真实评分，不预填结论） |

---

## 一、为什么要做这件事

M4-1 的自动指标、M4-2 的留出对照、M4-4 的消融实验，用的都是**机器尺子** ——
它们能证明「合规、结构完整、跨主题不雷同」，但回答不了一个问题：

> **一个带班老师拿到这份教案，会不会真的敢照着上？**

这个判断只有教师本人能给。所以 M4-5 是一次**人的验证**，也是三门评估里唯一的
外部效度来源。

**它判什么**：教案的**可用性**（好不好用），不是合规性（能不能交付，那是 W4 的事）。

---

## 二、设计：单盲混装评分卡

### 2.1 核心设计

| 要素 | 做法 |
|---|---|
| **盲** | 教师**不知道**哪份来自系统、哪份出自人手；材料里没有任何来源标记 |
| **混装** | 系统产出与人工范例**混合**，按固定随机种子打乱后编号为「教案 A/B/C…」 |
| **对照** | 对照组 = 语料里真实教师手写的教案（即人工水位）；实验组 = 系统产出 |
| **同一把尺子** | 所有卡片用**同一版式、同一套量表**，避免因呈现差异造成系统性偏差 |
| **单盲** | 教师盲、组织方不盲（持 `4_分组密钥.md`，评完开封） |

### 2.2 为什么这样设计

- **为什么要混装而不是只评系统产出**：只评系统产出只能得到绝对分，
  没有参照系就说不清「3.8 分算好还是不好」。混入人工范例后，
  「系统产出 vs 人工水位」的差值本身就是结论。
- **为什么不做成同主题 A/B 对照**：那需要为每个对照主题额外生成一份系统教案，
  且会引入「同一主题两份」这一不自然的呈现；混装评分卡样本效率更高，
  也让教师始终处在「评教案」而不是「挑不同」的心态。
- **为什么把单次时长归一为 30 分钟**：语料本就是 30 分钟主题课格式，系统也照此配置，
  归一后消除该维度上的噪声。（详见 §6 指纹剥离）

### 2.3 材料构成（共 6 份）

| 组别 | 份数 | 来源 |
|---|---|---|
| 系统产出（实验组） | 3 | 《国庆节到了》《穿鞋子》《音乐做动作》 |
| 人工范例（对照组） | 3 | 语料中的《浓浓端午节》《清凉夏日》《我和我的同伴》 |

- 三份人工范例**刻意避开**被用作阶梯来源的那几份，避免教师把「范例」与「系统」对上号。
- 编号 → 来源的对照写在 `4_分组密钥.md`，**评完再开封**。

## 三、评测维度

### 3.1 五个维度（各 1–5 分，可打半分）

| 编号 | 维度 | 看什么 |
|---|---|---|
| D1 | 目标可测性 | 活动目标是否具体、可观察、可评价；是否与主题、年龄相称 |
| D2 | 分层与个别化 | 是否照顾到不同能力水平；支持方式是否由多到少形成梯度；个别化目标是否落得下去 |
| D3 | 环节完整性 | 教学过程是否完整（引入—展开—结束）、层次清楚；各环节时间分配是否合理 |
| D4 | 材料与环境 | 材料是否具体、拿得到、用得上；环境布置与安全提示是否到位 |
| D5 | 教师语言与可操作性 | 教师语言能否照着说；指令是否清楚适龄；拿到手就能上课的程度 |

**分值锚点**：1 明显不足 / 2 有待改进 / 3 基本合格 / 4 良好 / 5 优秀

### 3.2 附加问题

- **Q6（必答）** 现在就要上这节课，这份教案你能怎么用？
  `可直接使用 / 小改一下就能用 / 需要较大修改 / 基本不能用`
- **Q7（必答）** 最需要改进的一点
- **Q8（选答）** 最有价值的部分

## 四、实施流程

### 路线 A：电脑填写（**推荐**，收分零转录）

```bash
# ① 备料：抽题、脱敏、打乱编号 → 匿名卡片 / 打印版 / 回收表 / 封存密钥
PYTHONUTF8=1 "$PY" scripts/lesson_docx.py blindeval

# ② 发卡：把卡片包成可直接在电脑上填的 Word 评分卡 + 建回收夹
PYTHONUTF8=1 "$PY" scripts/lesson_docx.py blindform --teachers "张老师,李老师,王老师"

# ③ 教师填写：打分格是下拉选择；每份教案正文就在它那张评分表正上方
# ④ 回收：教师把填好的 docx 丢进 data/blind-eval/回收/

# ⑤ 读回 + 统计：自动写回收表并按来源分组
PYTHONUTF8=1 "$PY" scripts/lesson_docx.py blindform --ingest
```

- **为什么用 docx 而不是网页**：教师是在自己的电脑上填，不是填在线表单。
  HTML 版只能打印，不能勾选；docx 里打分格是**下拉控件**（点一下出选项），
  选中的值以纯文本存在文档里，脚本能直接读回 —— 于是「教师填的**就是**最终数据」，
  中间没有组织方照抄一遍的环节。
- **兼容性兜底**：下拉用的是 OOXML 内容控件，Word 2013+ 与较新版 WPS 都支持。
  万一软件不认控件，格子退化成一段普通文字，教师直接改写即可，
  解析逻辑同样认「手打的 4」「手打的 4.5」。
- **缺填会报**：`--ingest` 逐份检查 D1–D5 有没有漏、Q6 有没有选、Q7（必答）有没有写，
  并在 `回收/读取报告.md` 里留一份明细供人工复核。
- **口径不变**：读回后仍走 `blind_eval_pack.py --tally` 的同一套分组统计与判据，
  电子填写只改变了「数据怎么进来」，没有改变「分数怎么算」。

### 路线 B：纸质填写（备选，需要人工转录）

1. **打印**：打开 `data/blind-eval/打印版.html` → 浏览器「打印 → 另存为 PDF」→ 打印；
   或分别打印 `0_教师须知.md` / `1_评测量表.md` / `2_教案卡片/`。
2. **发放**：每位教师一套（须知 + 卡片 + 量表）。**不要**发 `4_分组密钥.md`。
3. **评测**：请教师独立完成、互不商量；单份 3–5 分钟，全套 **20–30 分钟**。
4. **回收**：把分数誊进 `3_回收统计表.csv`（一行 = 一位教师评一份教案）。
5. **统计**（评完、开封后）：
   ```bash
   PYTHONUTF8=1 "$PY" scripts/blind_eval_pack.py --tally
   ```
   输出「系统产出 vs 人工范例」的分组均值表与 Q6 分布。

> **换编号**：`--seed <整数>` 可换一套打乱结果；**实施中途不要改种子**，否则编号对不上。
> **两种路线可以混用**：`--ingest` 只覆盖「本次回收到的那几位教师」的行，
> 回收表里手工誊的其它行会原样保留。

## 五、判读规则（**先定好，再看结果**）

为避免事后解释，判据在实施前预设如下：

| 判据 | 通过线 | 含义 |
|---|---|---|
| **C1 绝对可用性** | 系统产出五维均分 **≥ 3.5** | 达到「良好」以上，教师认为基本可用 |
| **C2 相对水平** | 与人工范例的五维均分差 **≤ 0.5** | 与人工水位同一档，不是「明显不如人写」 |
| **C3 直接可用比例** | Q6 选「可直接使用 + 小改后可用」占比 **≥ 80%** | 教师愿意用，而不是只当参考 |

**三种结局**：

- **三者全过** → 系统产出达到「可交付给教师使用」的水平。
- **C1 / C3 过、C2 不过** → 系统可用，但与资深教师手写仍有差距；差距落在哪些维度，
  由 Q7 的开放意见定位，作为下一步改进方向。
- **C1 或 C3 不过** → 系统产出尚不能直接用于教学，只能作为备课参考；
  这本身是有价值的负结果，需在报告中如实呈现。

> ⚠ **样本量**：教师人数少（预计 2–5 人）时，均值差异不宜做显著性推断，
> 结论以**描述统计 + 开放意见**为主。方案不预设「一定更好」，也**不接受**只报有利维度的做法。

## 六、隐私与指纹剥离（合规红线）

材料包在生成时已做三层处理，并由 `scripts/blind_eval_pack.py` **整包复扫**把关：

1. **零姓名**：拿 37 人的真实姓名清单逐字比对，命中即替换为「小朋友」。
2. **零诊断/标签**：`自闭症`/`智力障碍`/`缺陷` 等词表逐字扫描，命中即替换。
3. **零来源指纹**：班级名（火箭班/闪电班）、人数、日期、授课教师一律剥离；
   「全班 12 名」这类**系统产出固定值**也已抹平（它会暴露来源）；
   单次时长统一为「约 30 分钟」；章节序号重排为连续，避免「一、三、五」这种跳号暴露来源。

> 扫描范围不止教案卡片，**连教师须知、量表、密钥、打印版一起扫**
> —— 说明性文字里写出禁词同样会踩线（本项目合规检查是子串扫描）。
> 实测 13 个文件全部通过。

**伦理**：教师自愿参加、可随时退出、无需理由；教师信息仅用于区分评分者；
材料仅用于本课程作业的效果验证。

## 七、已知局限（如实写进报告）

1. **主题不同质**：六份教案主题各异，不存在「同主题一对一」的严格配对。
   评测维度已尽量选为主题无关项，但主题熟悉度仍可能影响打分。
2. **单盲而非双盲**：组织方知道分组；原则上由第三方执行发放与回收更严谨。
3. **呈现形式有差**：系统产出与人工范例的字段完整度不同（例如系统产出有
   「环境与安全」「备选方案」，人工范例以叙述为主）。教师须知已提示「按内容实质判断」，
   但形式差异仍可能带来偏好。
4. **样本量小**：教师人数有限，组间差异只能作定性参考。
5. **评价者可能认出材料**：若教师来自语料所属园所，可能认出人工范例。故人工范例
   已避开与系统产出有阶梯关系的几份；仍应在报告中说明。
6. **单人评分的一致性未知**：若只有 1 位教师，无法计算评分者信度。

## 八、与其它环节的边界

| 环节 | 判什么 | 尺子 |
|---|---|---|
| W4 `final_audit` | 能不能**交付**（版式与合规） | 规则 |
| M4-1 自动指标 | 机器可算的**绝对**质量证据 | 规则 |
| M4-2 留出对照 | 换主题还**成不成立** | 规则 |
| M4-4 消融实验 | 每个模块**贡献多少** | 规则 |
| **M4-5 教师盲评** | 教案**好不好用** | **人** |

> M4-5 是**独立环节**，不与其他五项合并，也不由自动化替代 ——
> 它的价值恰恰在于「尺子握在人手里」。

## 九、复算与产出

```bash
# ① 备料：生成材料包（默认种子，落到 data/blind-eval/）
PYTHONUTF8=1 "$PY" scripts/blind_eval_pack.py
#   README.md / 0_教师须知.md / 1_评测量表.md / 2_教案卡片/教案-{A..F}.md
#   3_回收统计表.csv / 4_分组密钥.md（封存）/ 打印版.html

# ② 发卡：把匿名卡片包成可填写的 Word 评分卡 + 建回收夹
PYTHONUTF8=1 "$PY" scripts/blind_eval_form.py --teachers "教师1,教师2,教师3"
#   5_教师评分卡/评分卡-模板.docx、评分卡-<教师>.docx
#   回收/_把填好的评分卡放这里.txt

# ③ 收分：读回教师交回的 docx → 写回收表 → 直接出分组统计
PYTHONUTF8=1 "$PY" scripts/blind_eval_form.py --ingest
#   回收/读取报告.md（解析明细，含缺填提示）

# 备选：只统计不解析（纸质路线 / 手工誊分后）
PYTHONUTF8=1 "$PY" scripts/blind_eval_pack.py --tally
```

> 两个脚本的分工：`blind_eval_pack.py` 备料（抽题 / 脱敏 / 打乱 / 封存密钥），
> `blind_eval_form.py` 管**收发**（发下可填的 docx、收回分数）。
> 渲染功能在 `src/lpa/blind_form.py`，两个入口共用同一套解析逻辑。
