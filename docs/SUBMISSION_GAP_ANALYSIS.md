## 三、问题一：人工测评（M4-5）是否确有必要？

### 结论：不必要。从课程评分角度，它对总分贡献为零。

### 依据（逐条来自通知原文）

1. **六个核心模块里没有「用户评价」这一环。** 通知第三节列明的六部分考察对象是：
   场景定义、架构实现、运行验证、异常防护、调试复盘、复现指引。**「教案好不好用」
   这个由教师判断的维度，不在任何一项里。**

2. **评分细则（第四节）的 100 分里，没有一分是评「人工测评」的。** 六个模块的
   优秀档判据全部是**工程可核验物**：拓扑图、Prompt、工具定义、Trace/日志、兜底策略、
   排错记录、复现指引。**没有一条要求「经过用户/专家评审」。**

3. **唯一沾边的是创新分第 2 条「定量评估体系」(+2)，但通知明确举例是
   *自动化*评测方法**（原文：「引入了**自动化评测方法**（如基于 Ragas、准确率评测集对
   Prompt/检索/工具调用进行量化打分）」）。**人工测评不在此列**，自动化评测才加分。

4. **人工测评能带来的，只是在「五、调试复盘与反思」里写一句「后续将补充真人盲评」**
   —— 属于伦理与局限性的自我披露，是**锦上添花的一两句话**，不是得分项。

### 量化对比（这就是决策依据）

| | 补工具调用 | 做教师盲评 |
|---|---|---|
| 覆盖的评分项 | 模块2（25分）+ 模块3（25分）+ 两条红线（-20~-25）+ 创新分（+2） | **0 项** |
| 预期分数变化 | **+15~30 分**（避免降档 + 避免扣分） | **0 分** |
| 剩余工作量 | 编码为主（工具集 + Agent 循环 + Trace） | 招募教师 + 协调 + 回收 + 分析 |
| 不可控因素 | 低（自己可控） | **高**（教师招不到 / 不按时交 / 样本量不足） |
| 失败后果 | —— | 白耗时间，且**挤占了本可以做对的事** |

**收益差一个数量级。**

### 但不要全废 —— 三条保留意见

1. **M4-1/M4-2/M4-4/M4-3 是另一个故事，千万别一起降级。** 这四件构成的
   「自动指标 + 留出对照 + 消融 + LLM-as-judge」证据链，**正是创新分第 2 条要的东西**。
   报告里应当**显式包装成「专属测试集 + 自动化评测体系」**，把四份报告作为附录证据。
   这是本项目相对其他同学**最硬的差异化优势**，+2 分基本稳拿，且顺带让模块 3
   「数据真实可信」的判据站得住。

2. **如果带教老师就在手边、愿意花 20 分钟**，那就顺手收 1–2 份。
   材料（匿名卡片 + 可填 Word 评分卡 + 自动回收脚本）**已经全部建好**，
   边际成本确实很低，收来的数据放进报告「运行效果」一节做**人机一致性对照**
   （M4-3 × M4-5）能加一点可信度。**但这是「顺手」，不是「任务」。**

3. **招不到人时的正确写法**：在报告 §5.2 局限性里明写
   「真人盲评材料（匿名混装 + 双盲评分卡）已构建就绪，受学期内时间限制尚未完成回收；
   本报告采用 LLM-as-judge 作为代理证据，并已披露其同族自偏好偏差」。
   **这是诚实的工程反思，本身符合模块 5 的评分取向** —— 比硬凑数据好。
